# 《潮钟诸境》：宏大世界的分层规划示例

> **未生成的规划示例。** 本文只有设计意图、预算与生产安排，没有新增群系数据、
> PNG、建筑几何、生物模型、资源包或游戏存档。下列名称和 ID 都是拟定目标，
> 不是已存在内容的证明；也不修改《月蚀诸峰》已验收的数据。

“宏大”在这里指地域差异、远近探索的节奏，以及内容之间能解释得通的关系，
不是把每个容量上限填满。这个例子可以借鉴《月蚀诸峰》的统一材料语言，
但不要求复制它的配色、Boss、建筑轮廓或数量；换一个用户设定，应重新设计这些选择。

## 1. 先确定一段能指导取舍的世界意图

潮汐停止之后，旧王国的钟声留在不同地貌里：海湾居民靠灯塔辨识归路，湿林保存
修灯知识，赤砾商道供应耐热材料，北潮断岸留下灾变证据，山冠上的巨钟仍在鸣响。
玩家是沿旧灯路寻找失散钟片的旅人；最终成果不是征服所有地点，而是让一次远行
拥有出发、绕行、回访与归来的意义。

这段意图放在 **`WorldDesignPlan.goal`**。下列宏观区域只是在文本中组织内容的
设计分组：不是新增的地域注册系统，不使用 `region` / `faction` ContentKey，
也不在 JSON 中发明 `regions`、`routes`、`productionBatches` 等字段。

## 2. 五个区域：每处改变至少三种体验

| 规划地域 | 拟采用的群系与辨识方式 | 建筑、资源与生物职责 | 旅行节奏与留白 |
| --- | --- | --- | --- |
| **晨盐回湾** | 碎镜浅海、晨盐沙岸、风铃原野；浅水反光、低矮风障、开阔视线 | 潮盐港群组、潮标灯塔；木材与基础补给优先可见；海岸小型生物承担初期材料来源 | 短程安顿，再去相邻可达地形探索；岸线保留无人建设的空段，避免处处都是奖励点 |
| **苔灯旧路** | 苔灯湿林、赤页丘陵；低雾、林下灯色、不同密度的树冠 | 苔灯修院群组、钟页藏馆、根径营地；获得修灯材料与旧事线索；林间普通敌人提供可重复材料来源 | 视线收紧、转弯较多；院落形成休息点，林地不是持续战斗走廊 |
| **赤砾商道** | 琉砂旱岭、余烬峰台；暖色裸岩、少量植被、坡地露头 | 赤砾采场、余烬窑站、沙风瞭台；资源来自开采场与普通敌人，而非所有地点都放同一种箱子 | 中程资源远征；在开阔段与局部遮蔽之间交替，不以新维度或高空飞行撑大尺度 |
| **北潮断岸** | 北潮黑礁、霜桥高地、沉钟海沟；黑色礁石、冰冷水色、破碎岸坡 | 黑礁号台、霜桥、倾斜钟楼；第一名 Boss“沉钟行刑者”提供中段转折 | 较长的危险绕行，可从干地退回；断桥是地点构图，不承诺跨区域自动铺出连续道路 |
| **苍辉钟冠** | 苍辉山脊、寒钟诸峰；清晰远景、冷暖峰顶差异、稀疏植被 | 共鸣王城地标、冠阶祭所；第二名 Boss“苍辉守望者”连接结局材料 | 登高前有补给间歇；高潮之后用主线交付收束“归潮”，不伪装成已经实现的海湾到访检测 |

结构预算中的 **3 个群组** 是潮盐港、苔灯修院、共鸣王城；**13 个独立地点**
是潮标灯塔、摆渡小屋、盐仓、根径营地、钟页藏馆、断水渡槽、赤砾采场、余烬窑站、
沙风瞭台、黑礁号台、霜桥、倾斜钟楼、冠阶祭所。摆渡小屋、盐仓与断水渡槽补充
日常生活和过渡空间，不再各自扩成一套完整城镇；摆渡小屋也不暗含已实现的 NPC 摆渡服务。

拟采用 **12 个群系定义**，不是五个区域各复制一套群系：

| 地形带 | 拟定分区（括号中为逻辑 ID） |
| --- | --- |
| DEEP_WATER | 沉钟海沟 `sunken_bell_trench`，覆盖该带 |
| SHALLOW_WATER | 碎镜浅海 `mirror_shallows`，覆盖该带 |
| COAST | COLD：北潮黑礁 `blackreef_coast`；TEMPERATE/HOT：晨盐沙岸 `saltwake_coast` |
| FLATS | ARID：风铃原野 `windchime_meadow`；HUMID：苔灯湿林 `mosslamp_wood` |
| HIGHLAND | COLD：霜桥高地 `frostbridge_upland`；TEMPERATE：赤页丘陵 `redleaf_hills`；HOT：琉砂旱岭 `glassand_ridges` |
| PEAKS | COLD：寒钟诸峰 `winterbell_peaks`；TEMPERATE：苍辉山脊 `azure_crown`；HOT：余烬峰台 `ember_tablelands` |

未指定的气候轴覆盖整轴；这张表在语义气候格上形成 **36 格无重叠的设计分配**。
它尚未写入 `BiomePlan`，更不等于实际地图已经有了这些海岸和山脉。
群系行为温度、表面、植被、雾色还要与对应角色一起设计，不能只改显示名称。

宏观区域会共享群系。气候选择与地形噪声不负责保证这些分组是连续行政区，
也不保证“北潮”一定在世界坐标北方。若需要关键地形位置，可使用既有 terrain
anchor 能力表达局部意图，再核验其实际效果；anchor 不是群系锁定、道路连接或
建筑必定放置的承诺。先读实际地形分布再决定是否调整，而不是凭地域名宣称相邻。

## 3. 探索路线：一条主线，两类自愿绕行

**主线体验顺序：** 晨盐回湾安顿 → 苔灯旧路识读 → 赤砾商道备料 →
北潮断岸对抗 → 苍辉钟冠高潮与归潮。

- **短环线**：港口—灯塔—草甸、修院—营地—藏馆。设计希望玩家一次补给能往返，
  用于建立当地资源与地貌记忆。
- **远征环线**：采场—旱岭—窑站、号台—断岸—钟楼。设计希望玩家主动准备并
 选择绕行方向，而不是连续刷同一套小屋。
- **留白段**：每段远征之间保留自然地貌和视线转换；建筑密度不是越高越好。
- **回访动机**：早期地点提供后段仍有用途的普通材料或叙事呼应，而非新增自动
 传送、动态商店、阵营声望或地区控制系统。

策划可暂用“短环线约 300–700 格、远征约 1200–2400 格”估计空间层次，
**这些只是待试玩调整的距离目标，不是已配置的半径、生成概率或到达时间保证**。
先看采样地图、地形通行性与结构实际放置结果，再决定是否扩大尺度。

计划主线为 **12 个单链任务**，分配到五段叙事的数量为 **2 / 3 / 2 / 3 / 2**。
玩家可以自由先探索其他地域；任务先后仅靠既有 prerequisites、主动交付与击杀计数。
“到访地域”“修好灯塔”“选择商会”只可作为文字目标，除非另有真正实现；当前
示例的可执行目标只使用 `deliver_item` 与 `kill_creature`，不发明探索触发器。

### 关键材料链先证明来源，再画漂亮的奖励图

| 计划中的需求 | 拟实施的来源 | 避免的软锁 |
| --- | --- | --- |
| 首段交付 8 枚盐潮碎片 `brine_shard` | 潮标灯塔的固定容器计划放 8 枚；普通海岸生物也计划有正概率掉落 | 建筑不一定生成在近处，另保留可重复来源；容器内容尚待真实绘图验证 |
| 中段交付 1 枚清钟核心 `clear_bell_core` | 击杀“沉钟行刑者”的前置任务 `quiet_drowned_bell`，领取奖励固定获得 1 枚 | 不让交付任务仅靠自己的奖励解锁；不把 Boss 的随机掉落当唯一来源 |
| 结局交付 1 枚共鸣种子 `resonance_seed` | 前置击杀任务 `still_sky_bell` 固定奖励 1 枚；最终 `return_tide` 主动交付 | 先领取前置奖励再交付，不把持有、拾取或提前击杀当自动完成 |

固定箱子是有限供给；后续多次交付要扣除之前已经消耗的数量。互斥建筑变体的
箱子不是同时存在，不相加凑预算。还要独立检查目标生物的栖息地、结构放置
条件与关闭掉落时的主线路径。上述是生产前来源设计，不是已证明可通关的实测。

## 5. 内容预算：先留空位，再扩大世界

执行前读取 `worldsmith_begin_world` / `worldsmith_get_content_framework` 返回的
**`authoringBudgets`**，对照当前版本的真实上限。下面的“作者分配”是本例的
设计预留，不是新增校验硬阈值；容量也不是性能或美术品质的保证。
例如查 `structures.maxCatalogTemplateVoxels` 与 `structures.maxPlanAuthoredCells`
时，要分别记整包模板总量和单方案量；`biomes.independentDefinitionLimit: null`
只表示没有独立群系数量 cap，不表示其他共享限制被取消。

| 项目 | 本例作者分配（未生成） | 当前源码约束 / 核验点 |
| --- | --- | --- |
| 计划目标 / 关系 | 118 个目标，关系先控制在 320 条以内 | 512 targets / 2048 links；完整世界的必要类别和真实连接仍须满足 |
| 共享内容目录 | 随每批统计实际 entries，不以 118 个设计目标直接代替 | `sharedCatalog.maxEntries` 当前为 16,384；别名和被引用蓝图等也会占目录条目 |
| 群系 / 地物 | 12 群系、14 地物 | 群系无独立数量上限声明；仍受计划、文档与每群系生态预算约束 |
| 结构定义 | 16：2 个常规群组、1 个地标群组、13 个独立地点 | 整包最多 48 个结构定义；不把群组组件当新结构数量重复统计 |
| 独立 blueprint 模板 | 约 29：群组分别预留 6 / 4 / 6 个，独立地点 13 个 | 整包最多 64 个 distinct blueprints；变体也消耗模板总工作量 |
| 模板 / 执行方案体素 | catalog 总和先控制在 650,000；单个执行方案先控制在 180,000 | 所有独立模板与变体共享 1,000,000 体素 catalog 额度；单 plan 262,144，含 AIR |
| 自定义方块 | 16：STONE 8、WOOD 4、METAL 2、GLASS 2 | 四个 profile 各 32 槽，不能把闲置 WOOD 槽当成额外 STONE 槽 |
| 生物 / Boss | 14 生物，其中 2 个真实 Boss | 生物 128；计划 Boss 最多 16；Boss 不再重复计作额外生物 |
| 普通物品 | 24 | 每世界 256；不是无限扩展的新功能物品系统 |
| 主线 / 叙事 | 12 个线性任务、5 个 beat、1 个 theme | 任务最多 64，单链；theme 的 beat 最多 64，各引用仍需成立 |
| 地形 / anchor | 1 个 `terrain/main`、3 个计划地形 anchor | 这里只计设计目标；具体字段、范围及几何效果继续服从地形契约 |
| PNG | 初版约 54 个，制作期留至 96 个句柄；PNG 总字节作者目标 ≤16 MiB | 256 个资源；单 PNG 4 MiB、总 64 MiB、总解码 16 Mi 像素、边长 2048 |

118 的口径是 **12 群系 + 14 地物 + 16 结构 + 16 方块 + 24 物品 +
14 生物 + 12 任务 + 5 beat + 1 theme + 1 terrain + 3 anchor**。
29 个组件模板在此不另立 blueprint 目标；如果之后要逐一加入计划，须同步增加分母，
而不是偷偷扩大制作范围后还沿用旧进度。

54 个 PNG 的估算口径是 40 个方块/物品纹理、12 个普通生物纹理、2 个 Boss 纹理。
若暂按 64² / 128² / 256² 像素制作，对应约 **491,520 解码像素**；这只是尺寸
假设下的算术，不是已有文件统计。真正字节数、句柄复用和 UV 匹配要读构建回执。

植被也留余量：作者目标为**每群系 ≤48 次尝试/区块**，真实上限为 64。
地表/水生 patch 的预算是 `round(density × 24) × patch.attempts`（正密度至少一次），
还要加同群系树木、石块等成本；例如草 0.5 × 1 次、花 0.25 × 2 次，贡献为
12 + 12 = 24，而非两个不到 1 的“小数所以很便宜”。树冠大小与分支同样影响预算。
所有地物 density 仍须处于 0..1；预算满足之后再看真实视觉是否过稀或重复。

## 6. 按依赖生产，不按地域复制五遍同一套目录

| 批次 | 新增工作与边界 | 放行依据 |
| --- | --- | --- |
| **B0 意图与分母** | 固定五段旅途、118 个目标口径、稳定 ID、来源链、预算；先把完整计划和主题草稿讲清楚 | 所有目标有职责和连接，没有未实现系统的承诺；字段与数量自洽 |
| **B1 海湾代表切片** | 先做 2–3 个相接气候角色、共享材料、一个小探索地点、普通生物及最早交付链；不是再建一个“最终缩小版世界” | 真实纹理、UV、绘图、入口/容器与模块回执；完整模式里其余目标仍保持未完成 |
| **B2 湿林与基础复用** | 扩展湿林/丘陵、修院群组；只复用材质与工具函数，不把港口外形换色当新地域 | 对照海湾实际预览，检查轮廓、密度、视线和补给差异；保持既有资产句柄 |
| **B3 旱岭与断岸** | 扩展资源远征、独立地点及第一名 Boss；完成清钟核心的真实来源和交付链 | 群系配置与地形采样、真正的 typed encounter、净空/奖励与前置消耗检查 |
| **B4 山冠高潮** | 地标组装、第二名 Boss 和最后两个任务；先检查共享 catalog / plan 体素预算再加装饰 | 实际组装、关键视角、阶段参数、结局固定奖励；不把高生命值等同于 Boss |
| **B5 补缺与交付** | 只补计划缺口、修诊断和最大视觉问题，再写包、导出 `.wspack`、读回与原生验证 | 分开记录目标覆盖、资源文件就绪和当前原生激活；不要把预览或规划图当已游玩世界 |

每批沿用同一 session、最新 revision 与已完成的 job / asset / drawing ID。
修改一个输入只重建受影响内容；不因“进入下一区域”清空状态、重画所有纹理或
重复申请正在等待批准的 job。若确实削减范围，先与用户确认并更新计划，不通过
删除未完成目标或降低模式来伪装进度完成。

阶段 B1/B2 不要求完整世界写包成功：全量目标尚未实现时，先使用领域构建与预览
检查代表切片，完整覆盖门禁留到 B5。若只需要一个可独立交付的小样，应明确另立
那个小样的范围，而不是悄悄降低原有完整世界承诺。

## 7. 这份规划没有保证什么

- 地域相邻、出生距离、旅行耗时、建筑一定放置、道路跨区连通，均需实际地图/原生检查。
- 一次场景截图不证明所有地形都能容纳建筑；一次来源静态检查不证明主线已经通关。
- BossSpawner 是受玩家距离、碰撞与附近实体条件约束的局部遭遇；不是全局唯一 Boss。
- 世界规则和叙事节点不是任务脚本；普通物品的名字不自动赋予导航、钥匙或护盾功能。
- 创建页的目标进度是草稿覆盖；`.wspack` 就绪和本次原生激活各需要独立回执。
