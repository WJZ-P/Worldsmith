# 可编程能力：记忆旧庭

这一小段场景展示的是**源码程序和通用运行时**，不是预置技能名称的清单。

进阶样板：[旧庭盟灯：三份源码协作、临时世界编辑与灯息护盾](gameplay.md)；
表现样板：[通用表现、动画与可控投射物](visuals.md)。

## 三份真正不同的程序

源码保存在 `core/src/main/resources/worldsmith/abilities/examples/`，并作为 `abilities` 模块的一部分随世界包保存。

| 源码 | 程序行为 | 玩家应对 / 验证重点 |
| --- | --- | --- |
| `echo_positions.ability` | 自定义函数、局部变量、列表、`repeat` 和 `for`；分三次记录坐标，随后按旧坐标逐点结算 | 看到预兆后持续移动；坐标不会追踪玩家。程序显式调用可见性查询，石墙可挡住这一程序的伤害 |
| `fragile_channel.ability` | `while` 和 `wait`；`on hurt` / `on block_break` 修改共享状态，中断后走虚弱分支，否则释放范围效果 | 攻击施法者，或打破起点附近六格内的方块；不是把蓄力伤害简单调低 |
| `branching_orb.ability` | `on projectile_hit` 根据 `event_tag` 分支；首枚 seed 火花碰撞后发射两个 spark，spark 不再分裂 | 碰撞回调、子弹生命周期和分支都在源码中；原生投射物本身不附带这份脚本的伤害逻辑 |

`echo_positions` 的**同一个程序 ID**同时被以下入口调用：

1. `lantern_guardian` 的 `CreatureAbilityBinding`。
2. `echo_wand` 的 USE → `run_program`。
3. `echo_pedestal` 的机关动作 → `run_program`。

守卫使用空 `boss.phases` 的展示资料；没有固定二段 / 三段阶段表。作者可在脚本 `state` 中写任意受预算约束的流程。

## 场景路线

导入新生成的 `build/ability-runtime/programmed-trial.wspack`，进入原点附近的旧庭：

1. 按 J 看日志，左侧箱子取铁块、剑、面包及三根试杖。
2. 补全灯台，召出记忆守灯人；离开其记录的光圈，反击并拾取铜钥。
3. 主手持钥使用铁门左侧石基，完成原来的通路任务。
4. 右侧钻石基座可重复触发回声程序，用于对照三个宿主的同源行为；它不是通关条件。
5. 脆响试杖会把自己变成施法者；蓄力期间受伤或破坏附近方块，可观察自己的虚弱分支。分星试杖展示投射物回调。

现有物理祭台、钥匙掉落、门、日志目标和出生地结构都被复用。纹理只是确定性的测试美术；这里没有宣称已完成完整世界、多人平衡或真人十五分钟体验。

## 如何创作下一种能力

修改或新增 `AbilityProgramDefinition.source`，使用函数、变量、事件、等待和能力注册表里的函数。只有新增**引擎能力提供者**时才需要 Java / Kotlin；组合现有查询、效果和事件不需要新增技能枚举或改运行时。

例如，在回声程序里改采样次数、保存两个列表、按 `entity.health_ratio(self)` 选择不同循环，都是程序变化。函数名及版本在编译时检查；编译后的代码是随包源码的固定结果，重新打开世界不调用 AI 或外部编译器。

原生扩展采用带版本和参数签名的 capability 注册。核心测试用 `test.mark` 扩展同一标准注册表，然后由 `AbilityHost` 执行它，证明 VM 不需要知道这个新增函数名。

## 边界

- 源码合作式执行，有每 tick、总操作数、生命周期、堆栈、队列和值大小限制；无限循环不会占住服务器线程。
- 世界查询、粒子和投射物有距离、数量、区块加载及所有权限制。
- 攻击判定在服务器；本例主动使用 `world.visible`，不是对所有未来程序强加同一种几何或视线规则。
- 卸载、死亡或取消结束正在运行的指令与资源；保存的 `state` 不等于保存等待中的 PC、目标或投射物。重载不接着执行半途伤害。
- 机关事务保证的是程序启动的预留与提交；程序稍后造成的伤害不属于机关方块回滚事务。
- 新包使用当前能力模块格式；旧包和旧存档保持原样，不会被就地迁移。

## 构建和验证

`AbilityRuntimeExample.main` 导出新包、可读 bundle 和三份 `.ability` 源码；输出目录默认是 `build/ability-runtime`。

原生验证通过 `-PmechanicsGameTest -PabilityRuntime` 启用独立环境，保留原有两个机关测试。客户端演示另加 `-PabilityClientTest`，使用隔离世界和真实渲染管线保存截图。测试结果以生成的报告为准，文档不是已运行的证明。
