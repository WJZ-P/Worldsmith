# 世界观驱动创作工作流：实施计划

状态：**一期实现完成，JAR 编译及 111 项选定自动化测试通过；未启动游戏或进行实玩。** 日期：2026-09-14。

## 0. 已确认的产品决策

- 用户 Prompt 先扩写成完整、可追溯的世界观，再派生地形、群系、建筑、生物、方块、物品和任务。
- **AI 自检后自动继续**，不增加人工确认停顿。审核来源明确标记为 AI，不冒充用户批准。
- 主线体验、区域生态、资源来源、交付消耗和奖励意义共同规划，避免生产完内容后再拼任务。
- 改造创作编排层；复用现有生成器、Draw SDK、资源管线、任务运行时和工程校验。
- 直接在 `main` 工作。用户随后明确授权完成验证后分批推送，再正常关机。
- 初始验证边界为编译；用户随后授权运行所需指令，本次已执行 97 项 Core 流程测试与 14 项原生类/旧功能回归，共 111 项通过、0 失败、0 跳过。未启动游戏或进行 GUI/实玩操作。

## 1. 目标与非目标

### 目标

每个产出都能回答：它源于哪条世界设定、承担什么作用、与哪些其他内容衔接、实际实现是否兑现了设计。
设定改变时，显示受影响内容与待复核项，保留已完成资产；恢复会话时继续当前缺口。

### 一期非目标

- 不重写地形算法、建筑绘制器、生物 AI、物品技能或任务执行器。
- 不增加 NPC 对话、阵营声望、经营交易、分支任务、动态世界改造等新玩法。
- 不把文学描述自动解释为游戏机制。用户明确要求但当前机制尚未覆盖的能力保持为待解决范围决策，不通过改写成背景故事来宣称完成。
- 不更改现有 `.wspack` 格式、不可变内容哈希、旧包加载规则或已有存档。
- 不引入 Mod 内隐藏 LLM。扩写、任务书设计与语义审稿由连接 MCP 的 AI 执行。
- 不建设逐字段增量构建系统；一期采用有界作者节点、文档摘要与显式依赖。

## 3. 作者态数据模型

所有新数据首先保存在创作 session，不新增运行时内容模块或 `ContentKey` 类型。
新字段应支持旧会话反序列化；空默认值不改变旧对象的既有含义。

### 3.1 WorldBible：唯一设定事实源

- **需求依据**：原始 Prompt、用户硬约束、允许扩写部分、AI 假设、待解决问题。
- **核心设定**：世界前提、历史因果、玩家身份、世界规则、主要冲突。
- **世界组成**：区域与过渡、文明与聚落功能、生物生态位、资源来源与用途、视觉及声音语言。
- **体验骨架**：探索节奏、主线节拍、资源与奖励链、关键遭遇的意义。
- **实现范围**：哪些内容类别是本次承诺、是否包含 Boss、设定与已安装机制的对应关系。
- **稳定作者 ID**：规则、地区、历史事件、资源体系、剧情节拍等可单独引用；这些 ID 与实际内容 ID 分开。
- **叙述性质**：区分作者事实、世界内传说与角色认知，避免把叙述视角差异当作逻辑矛盾。

结构化 WorldBible 是唯一维护入口；可阅读的 MD 是确定性渲染结果，不独立编辑第二份正文。
现有 `WorldTheme` 由 AI 基于当前 WorldBible 派生为符合运行时字段预算的摘要；其内容摘要与来源版本被记录和审核，不另立一套世界事实。

### 3.2 ModuleBrief：派生创作任务书

每份任务书包含：

- 稳定任务书 ID、目标 `ContentKey` 列表、标题与实现职责。
- `basisRefs`：引用的世界设定节点，以及需要体现的具体设定主张。
- 实现选择：区域/生态/功能/材质/能力/声音等领域相关要求。
- 跨内容依赖：来源、消耗、用途、任务前置、奖励、建筑与遭遇位置等。
- 必需验收项：实际字段、引用关系、模型/几何预览或现有检查能够提供的证据。
- 尚未解决的范围决策，以及创建时采用的世界观版本与依据摘要。

任务书只维护实现选择。若设计过程中新增或修改世界事实，应先回写 WorldBible，再更新相关任务书。
任务书依赖和运行时关系属于不同层次：制作顺序要可调度，但叙事或材料的相互关联不直接等同于非法依赖环。

### 3.3 审核与派生记录

分开保存世界观审核、内容实现审核、确定性工程检查。
AI 审核按条目记录：**需求/设定 → 实现主张 → 具体字段或证据 → 结论 → 矛盾及修复项**。

审核绑定实际审查的 WorldBible、任务书及内容快照摘要，并记录来源为 AI。
程序检查报告格式、覆盖范围、引用、摘要时效与未解决阻断项；不将其宣传成“已自动证明故事合理”。
仅有 `basisRefs`、泛化赞语或任意一致性分数不满足审核记录要求。

## 4. 修订与失效规则

区分 session 的并发写入 `revision` 与世界观的语义版本。所有作者态写入仍遵守现有 CAS 和原子持久化约定。

| 变更 | 失效范围 | 保留内容 |
|---|---|---|
| 用户硬约束、核心前提或全局规则改变 | 世界观审核、所有相关任务书与实现审核 | 既有草稿、纹理、绘制任务和冻结几何 |
| 局部区域、资源、物种等设定改变 | 引用该节点的任务书及依赖闭包待复核 | 不相关内容与其有效证据 |
| 删除仍被引用的作者节点 | 明确悬空引用错误 | 保留引用方，交由修复而非静默删掉 |
| 任务书或模块定义改变 | 对应内容实现审核失效 | 已有素材可继续复用 |
| 上传与当前内容无关的 PNG | 不使世界观审核失效 | 其余有效审核记录 |
| 当前模块实际引用的纹理/几何改变 | 该模块表现与实现审核失效 | 世界观审核及无关模块 |
| 已安装能力边界改变 | 涉及能力的可实现性判断待复核 | 既有内容与来源记录 |

失效是“需要复核”，不是删除或强制重生成。
对未知影响采用保守失效；不允许因无法精确分析而继续声称审核有效。
并发中的旧审核、旧派生结果和慢发布结果不得覆盖新修订。

## 5. 工作流和门槛

```text
需求解析
  → 保存 WorldBible
  → AI 世界观自检与必要修复
  → 区域生态 / 主线体验 / 资源奖励链共同规划
  → WorldDesignPlan + ModuleBrief
  → 代表性切片制作与复核
  → 按依赖扩展其余内容
  → 内容实现审核 + 既有工程检查
  → 冻结世界包 / 原生准备 / 发布
```

- 世界观通过当前版本的结构检查与 AI 自检后自动进入下一阶段；不显示“等待用户批准”。
- 同一版本、同一阻断项最多自动修复 3 轮；持续失败时返回具体阻断与所需范围决策，不循环自评。输入或修复对象实质变化后重新计算重试预算。
- 批量制作前必须具备有效世界观、计划与对应任务书。代表性制作在这些依据建立后进行。
- 读取契约、查看状态、诊断与复用素材的只读操作保持可用。
- 内容编辑后允许局部修复；最终审核必须针对实际待发布内容，而不是只审计划。
- 作者态门槛覆盖相关高成本制作入口，并在 `write_pack` 与 `finish_world` 再次执行。
- `write_pack` 的 inline modules、恢复会话、绘制/生物重建与重试路径均纳入检查，避免绕开来源检查。
- 延续现有延迟原生加载行为：浏览世界包和世界观不会触发客户端资源重载。
- 当前 `COMPLETE_WORLD` 强制 Boss 的规则，改为新流程中的显式玩法承诺；承诺 Boss 时仍检查真实 Boss、遭遇与对应任务。

## 6. 模式、会话与资源包兼容

| 对象 | 一期策略 |
|---|---|
| 新 `COMPLETE_WORLD` 会话 | 记录新作者工作流版本，执行完整世界观驱动流程 |
| 新完整世界的内容范围 | 默认保留现有六类内容承诺；Boss 是否必需由需求与明确范围决定，其他类别的可选化不在一期扩散 |
| `WORLDGEN_ONLY` | 保留现有轻量范围；可复用已存在的设定，不强制补物品、任务或 Boss |
| `STANDALONE` | 保留单建筑/单生物入口，不强制完整世界设定稿 |
| 旧未完成会话 | 按旧工作流版本恢复；可显式升级，升级后根据已有内容补依据和复核，不删除成果 |
| 已发布世界包、嵌入存档 | 加载、游玩和原样重新嵌入保持现有行为，不追溯新增作者态门槛 |
| 导入的旧世界包继续创作 | 保留来源包；在新作者会话中补设定和任务书，不篡改原始包 |

一期完整 WorldBible、任务书和审核证据只保证随 session 持久化。
跨设备携带完整创作依据属于后续可选创作归档设计，不冒充当前 `.wspack` 已包含这些新数据。

## 7. 接口与上下文交付

在现有 MCP 服务中新增作者态接口，命名按现有工具规范落实：

1. 读取/更新 WorldBible，支持摘要、指定节点与 MD 视图。
2. 提交针对当前版本的世界观自检报告。
3. 原子读取/更新 ModuleBrief 集合与派生依据。
4. 提交针对当前内容快照的实现一致性审核报告。
5. 扩展现有 draft/progress：返回当前阶段、失效原因、缺口、精确下一步参数和相关设定引用。

契约按阶段、节点和目标分段返回；各模块获得“全局硬约束 + 相关设定 + 任务书 + 依赖”，而不是每次重读整个设定集。
新数据需要明确节点数、引用数、文本、报告条目和总字节预算，并保持 session 当前 8 MiB 持久化上限；超限报告诊断，不静默截断设定。

## 9. 必须覆盖的验收矩阵

| 场景 | 预期结果 |
|---|---|
| 单 Prompt 新完整世界 | 先保存、自检世界观，再派生计划与内容；自动继续 |
| 只有漂亮世界观正文，没有模块依据 | 明确缺少任务书/证据，不标记为一致性通过 |
| 所有内容只挂同一个 basisRef | 仍需逐项实现主张和实际证据，不靠引用数量过关 |
| 合法 ID 但任务动机/掉落来源与设定矛盾 | AI 审稿提供具体问题、设定出处与修复项 |
| 世界观说存在某能力，运行时没有对应实现 | 待解决决策保留，不凭叙事文本视为完成 |
| 交付来源自锁、后锁或有限补给不足 | 继续由现有工程检查阻断 |
| 有正概率来源但路程/成本不合理 | 标记体验审稿问题，不谎称静态来源检查已证明可玩 |
| 全局约束改变/局部设定改变 | 对应审核失效；不相关有效内容尽量保留 |
| 模块内容在审核后改变 | 旧审核失效；发布要求重新检查当前快照 |
| 旧审核迟到、旧发布结果迟到 | CAS/摘要检查拒绝覆盖新状态 |
| 世界观与报告超预算或有悬空引用 | 明确诊断，不自动截断或删内容 |
| AI 审核通过 | 展示“AI 已审核”，不展示“用户已确认”或“已实玩” |
| 连续自检失败 | 有界修复后报告实际阻断；不无限自动重试 |
| 旧包/旧存档/单件创作 | 兼容策略成立，不强制重生成整个世界 |
| 世界观/进度只读浏览 | 不编译结构、不加载纹理、不触发原生重载 |

## 10. 完成标准与后续边界

首期完成意味着：完整世界有持久、可恢复的设定依据；各模块能追踪来源；变更会触发正确复核；AI 审稿与工程检查共同参与发布。
不等于保证文学质量、随机世界实例放置、战斗平衡或实际游玩体验全部正确。

后续再考虑完整创作归档随包携带、更细增量分析、游玩采样与更丰富的任务/社会机制。
本计划列出的首期代码、契约、界面与回归用例已实现。验证报告位于本地 build/world-bible-refactor/delivery-report.json，构建日志与测试报告保留在对应构建目录；构建产物不进入 Git。
