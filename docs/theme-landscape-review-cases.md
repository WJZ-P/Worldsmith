# 建筑与地形：五组创作回归思考案例

这些案例用于发现主题在实现中是否丢失，不是新的运行时框架、固定建筑库或自动审美测试。
下方引文是可逐字使用的**示例玩家 prompt**；只有实际采用该 prompt 时，才将其中片段
写成 `WorldBible.requirements[].promptQuote`。本文推导的构图与参数属于作者选择，
不是玩家原话，也不是所有种子、地貌或规模下的最佳值。

每例先形成少量可核对的 REGION / STYLE / ECOLOGY / EXPERIENCE 事实，再写现有
`WorldDesignPlan` 目标与 `ModuleBrief.criteria`。建筑依赖地形或群系时，显式记录 brief
依赖，并保留两端的实现证据。本文 JSON 都是**标明所属位置的局部示范**，不是可直接
发布的完整模块。完整世界仍遵循既有范围与工程检查；单体研究不冒称完整世界完成。

字段依据以当前本地契约为准：[terrain](../core/src/main/resources/prompts/contract/terrain.system.md)、
[biome](../core/src/main/resources/prompts/contract/biome.system.md)、
[structure](../core/src/main/resources/prompts/contract/structure.system.md)、
[architecture](../core/src/main/resources/prompts/contract/architecture.system.md)、
[draw](../core/src/main/resources/prompts/contract/draw.system.md)、
[module_briefs](../core/src/main/resources/prompts/contract/module_briefs.system.md)。

## 1. 温和、无山峰的高原：让地平线成为主角

**逐字示例 prompt**

> 我想要温和开阔的高原，没有尖峰和夸张断崖。建筑像安静的观测驿站，低矮的生活空间围绕小院，远处能看到一个克制的观察标志，不要变成高塔森林。

**可见决定**

- 平缓的背景起伏和宽地平线，比持续抬高地面更重要；有明确观测场地才使用局部平台。
- 建筑用低翼、院落和一个有用途的观察点形成主次，而非每栋都长出尖塔。
- 高地的地表、基座与建筑结构共享材料来源，屋顶和少量标志仍有清楚分工。
- 到达路线先经过低空间，再显露观察点；院落和入口实际连通，不用文字代替台阶。

**支持字段与工具**

`terrain.shape.relief` 的一种起步示范：

```json
{"flats":0.75,"highlands":0.25,"peaks":0.0,"transitionWidth":0.16}
```

零权重排除该全局地形家族；同时检查其他 anchor、band 和高度参数，避免另行制造
与原请求冲突的高耸轮廓。`transitionWidth` 是噪声选择器单位，不是道路坡度；只选
一个地形家族时它不改变形状。`verticalScale`、水文和大陆尺度仍须共同设计。
若确有水平观测台，可为相关 anchor 使用 `relief.kind:"mesa"`，以 `surfaceY`、
`topRadius`、`roughness` 控制平台；`climateBias` 不由“高原”名称自动生成。
建筑使用 `placement.terrainFit`、foundation、access 与真实绘图；低屋顶采用实际 slab /
stairs 状态或合适的 ROOF 剖面，而非将所有同高屋面都铺成连续楼梯齿。

**常见错误反例**：只把 `verticalScale` 调高，再把陡峭山头叫作“温和高原”；或者复制
同一高塔改尺寸，最后只换草色。前者误解地形，后者丢失建筑主次。

**离线证据与边界**：查看参数中的零峰值权重、群系分布估计、平台剖面与同 frame
建筑群灰模。`worldsmith_preview_landform` 只检查指定 anchor 和显式
`incomingSurfaceY`；`worldsmith_analyze_biome_distribution` 是气候空间估计。
尚未证明整张地图没有局部陡边、实际出生地点温和或驿站确已放置。
较少轮廓段和较大的平面可能正符合安静主题，指标减少不等于退步。

## 2. 风暴海岸的低矮高脚聚落：支撑与避风比高度更重要

**逐字示例 prompt**

> 做一个风暴海岸上的低矮高脚聚落。住屋和仓棚贴近水面上方，靠短栈道与浅滩码头联系，入口有遮蔽；我想看见坚实的桩脚，不要漂浮平台或海边城堡。

**可见决定**

- 地貌有可辨识的浅滩、岸线和较深外海，建筑选择短跨距、低屋顶和背风入口。
- 抬高的是实际居住楼面，不是把整栋楼拉成高塔；桩、楼面、栈道和水线有明确剖面关系。
- 聚落轮廓低而连续，干燥室内与小型遮蔽停留处比开放大阶梯更符合主题。
- 桩脚材料、湿区基底和修补部位体现用途；避免逐方块随机染色假装海蚀。

**支持字段与工具**

海陆比例、海岸粗糙度、`shape.hydrology.oceanDepth` 与水域/海岸群系联合设计。
浅水群系名称并不证明其下方存在够近的实体支撑。
以下是 `placement.terrainFit` 的局部示范，画布基础 datum 为 Y=0：

```json
{
  "surface":"WATER_SURFACE",
  "maxHeightDifference":2,
  "foundation":{
    "mode":"PILLARS","material":"piles","maxDepth":8,
    "supports":[{"x":2,"y":0,"z":2},{"x":8,"y":0,"z":2},{"x":2,"y":0,"z":8},{"x":8,"y":0,"z":8}]
  }
}
```

`piles` 必须是根蓝图中的真实 palette key，解析为干燥、完整支撑方块。`PILLARS`
使用根局部 Y=0 的支撑点，最多 64 个；`maxDepth` 支持 1..16，本例 8 只是延伸预算。
它不创建浅滩：如果实际需要向下延伸的距离超过预算，候选点应失败，而非留下悬空桩。
检查所有支撑位置与总体 foundation 工作量，不只检查建筑中心水深。绘图中还须真实
画出基准面以上的柱、升高楼面、出入口与栈道；SDK `support(at)` 只声明支撑位置。

`WATER_SURFACE + NONE` 表达浮在水面上的结构，不符合本例坚实桩脚要求。
现有 `terrainFollowing` 本地道路适用于 LAND_SURFACE / SKY_SURFACE，且其独立贴地
建筑使用 NONE / FILL；不要将它与本例水面 PILLARS 组合当作现成水乡路网。短栈道可
作为真实刚性几何和连接端口创作，跨度与落脚条件仍需审查。
群系 `behavior.hasPrecipitation`、`temperature`、`downfall` 与环境色雾可配合气候意图，
并不安装持续风暴、海浪冲击或结构抗风模拟。

**常见错误反例**：将海洋深度调大，再用 `maxDepth:16` 宣称桩自动伸到任意海底；
或为了通过放置改成 NONE，仍称它为固定高脚聚落。

**离线证据与边界**：对照真实 foundation 声明、支撑点、模型侧视/剖切和栈道入口；
预检只支持其实际检查范围。未观察真实水深、各桩落点、波浪、夜间光照与生成结果。
更少的轮廓起伏、较低的建筑总高可能是正确修复；增添高塔反而破坏主题。

## 3. 火山口盆地：凹下去的中心与抬起来的环壁

**逐字示例 prompt**

> 我想进入一处古老火山口盆地，先看到高高的环壁，再逐步发现盆底的聚落和祭祀场。盆底与外坡要有不同的生态和材料，不要只是普通山谷染成黑色。

**可见决定**

- 地形有盆底、内壁、环脊和外坡四个可读部分；建筑采用适合盆底的低密度组团，
  让环壁仍是背景主体，不让每处建筑争当第二座火山。
- 到达过程有遮挡、转折和显露；入口台阶、门槛和短桥必须真实创作。
- 同一历史原因影响盆底资源、坡面材料和建筑用途；材质差异跟随环境，而非任意分区换色。

**支持字段与工具**

anchor 的 `relief` 局部示范：

```json
{"kind":"caldera","floorY":76,"rimY":144,"floorRadius":0.28,"rimRadius":0.66,"roughness":2}
```

`floorY` / `rimY` 是绝对高度，半径字段是扭曲半径的比例；`roughness` 的单位是方块。
这些值还须符合 terrain 契约的高度与半径边界。以 `worldsmith_preview_landform`
比较两个显式周围参考高度，看盆底、环脊和外侧回接，不把固定参考平面当作测得地形。
`biome.surface.rules[].conditions.anchor` 可按 anchor 的影响带布置表面材料；
其 min/max 是影响值，不是半径或高度。盆地中心影响高并不表示那里是“山顶”。

`placement.anchor.id` 将结构 pivot 关联到地标，默认不是自动寻找环壁上的理想位置。
需要偏置时使用真实 `offsetX` / `offsetZ`，并保留群系、terrainFit 和支撑限制。
海平面仍是全局 `seaLevel`；降低盆底可能使其接收默认流体，未新增独立火山口湖水位。

**常见错误反例**：只用负 `offset.amplitude` 压出一个凹坑，就宣称存在抬升环壁；
或只写“沿环壁道路”，却没有路径几何或可执行连接策略。

**离线证据与边界**：审查真实 caldera 字段、隔离剖面图、材料规则、建筑剖面与入口
两端证据。洞穴、bands、重叠 anchor、出生点与真实生成位置仍可能改变体验。
`maximumSampledGrade` 较高未必是坏事——环壁可以陡，通行路线另有要求；把整个盆地
优化成最低坡度，会消除玩家要求的地貌。

## 4. 极简盐地纪念场所：大片平面可能就是答案

**逐字示例 prompt**

> 做一片辽阔安静的盐地，纪念场所克制而肃穆：几面完整的大墙、长阴影、明确的门洞和大量留白。不要把空白填满花纹、窗格或热闹村庄。

**可见决定**

- 平坦背景与少数竖向面形成对比；以墙体厚度、门洞、转向和尺度关系表达场所，
  而不是靠彩色纹样维持辨识度。
- 墙后、门前和行走路径都设计留白；正面可以安静，背面和断面仍要有真实构造。
- 纪念结构与必要的功能空间可以有不同组织方式，不将整座纪念墙缩放成每栋建筑。
- “长阴影”是待观察的游戏光照意图，不由离线灰模阴影截图自动兑现。

**支持字段与工具**

可先研究 `shape.relief` 中 `flats:1, highlands:0, peaks:0` 的单家族方案，再协调
`landRatio`、`verticalScale` 和水文。单家族时扩大 `transitionWidth` 不会制造新变化。
在 dry saltland 的设计中，`hydrology.riverCoverage`、`lakeDensity` 可为零；如保留
干涸水道，则明确选择 `riverFill:"DRY"` 和匹配的 surface hydrology 条件。
`surface.base` 与有限、有原因的 `surface.rules` 表达盐壳和裸露底材，不默认铺满随机噪声。

建筑用现有 `worldTheme`、`themeFit`、`layoutIntent`、`distinction` 解释完整墙面的目的；
门洞、墙厚、通行和占用空间由几何及 access 兑现。`keepClear` 可声明画布内的留白区，
但它不自动清 AIR，也不替代实际路面和净空；`protect` 仅是 variation/decay 保护。

**常见错误反例**：看到 `visualEvidence.review` 提到大型共面板块，就为缩小
`largestPlanarPanel` 填入窗户与凸饰，反而毁掉原请求的完整墙面。

**离线证据与边界**：检查同 frame 的灰模等角图、材料图、门洞剖切、实际空白与动线。
最大平面大、材质少、轮廓变化少可以是保留理由，不是失败分数。正交灰模中进深可能
不明显，需联看等角和材料视图。实际太阳方向、长阴影、风沙、夜间环境与放置尚未验证。

## 5. 真正浮空的废墟：离地间隙与可达入口都要有依据

**逐字示例 prompt**

> 我想探索真正离地悬浮的废墟，岛底下能看见天空，不是从地面长出的高石柱。近处遗迹有清楚的入口和短廊桥，远处岛群留作稀疏的远景，不要整个天空都铺成一块石板。

**可见决定**

- 岛体下方有空气间隔，岛与岛之间保留空隙；破损边缘、厚薄变化和建筑残片共同表达悬浮。
- 近景路线用有限、真实连接的结构服务探索；远景岛群不是自动可达任务目标。
- 废墟与岛体共享一种构造/侵蚀逻辑，但建筑墙面不应只是岛体随机噪声的复制。
- 悬空的概念不等于给每个走道都挖断；保留必要的落脚和回路。

**支持字段与工具**

`terrain.shape.bands[]` 的一种局部示范：

```json
{"effect":"ADD","coverage":0.18,"minY":176,"maxY":240,"region":"OVER_OCEAN","scale":1.2,"thickness":0.8}
```

ADD band 提供独立岩体；参数须配合实际基底高度、海平面、洞穴范围和其他 bands。
高覆盖率可能连接成天花板；低 coverage 也不保证每座岛都与地面或其他岩体分离。
将 `peaks`、`verticalScale` 或正 offset 调高，得到的仍是地面连接的高度场，不是本例要求。

结构可使用 `terrainFit.surface:"SKY_SURFACE"`，配套实际 `verticalRange`、必要的
`minAirBelow`、foundation 与净空设置；它检查局部柱下的空气间隔，不证明整座岛在
三维上完全断开。短连接可研究支持 SKY_SURFACE 的既有 assembly roads，但跨度、
端口和路径搜索仍受限制，不承诺连接任意两岛。起始到达方式必须有真实支持；普通
气候 `spawnTargets`、名为“浮空入口”的字段说明或一段飞行传说均不等于已实现上岛。

**常见错误反例**：把一根很高、洞穴很多的石柱当浮空岛；或者拿只分析 anchor 的
`worldsmith_preview_landform` 图片证明 ADD band 已形成真实悬浮地貌。

**离线证据与边界**：核对 band 的独立密度体设计、垂直范围与后续操作顺序；查看可用
的离线密度采样测试和实际废墟/廊桥几何。anchor 隔离剖面不采样 bands，气候分布图
也不是岛群地图。尚未证明全岛断开、实际上岛路线、生成实例和远景可见性。
少一些岩体和构件可能改善悬浮感；以 nonAirCells 增长当作完成度会导向相反结果。

## 6. 横向复核：这些世界应在灰模里就不一样

| 案例 | 主要空间关系 | 应保留的空白/对比 | 不应自动追求的指标 |
| --- | --- | --- | --- |
| 温和高原 | 宽地平线、低翼、小尺度观察焦点 | 温和背景衬托克制标志 | 更多峰型、更高塔楼 |
| 风暴海岸 | 浅滩—桩脚—升高楼面—遮蔽入口 | 水线下支撑与上方低矮轮廓 | 任意水深都通过、更多竖向体量 |
| 火山口盆地 | 盆底、内壁、环脊、外坡及分阶段发现 | 大地形衬托盆内小聚落 | 全域最小坡度 |
| 极简盐地 | 完整墙体、厚门洞、转向与长视线 | 大墙与大片留白 | 最小平面面积、最多材料/饰件 |
| 浮空废墟 | 独立岩体、下方空气、有限可达近景 | 岛间与岛下间隙 | 最大方块数、最高地面山柱 |

回归时保持相同创作预算、视图和对照条件，记录“主题依据 → 实际决定 → 证据 →
最大的剩余问题”。不要给五个 prompt 同一套大厅、道路和山丘，只更换名称与颜色。
本表的差异也不是新配额：若另一种构图更符合该次请求，就说明依据并按实际结果核对。

几何统计描述物体，视觉判断解释其作用，两者可能指向相反修改方向。AI 审查、Core
检查、PNG、实际放置和真实游玩分层记录；这些案例没有启动 Minecraft，也不声称上述
五个世界已经生成或验证。详细流程见[联合设计指南](theme-landscape-design.md)。
