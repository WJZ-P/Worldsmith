# 方块构型与交互机制

`mechanics` 是格式 **7** 的第十个类型化模块。AI 可以组合**事件、相对方块构型、
主手成本、锚点状态与固定动作**，实际驱动召唤、开门、交料兑换，而不是只写一段仪式叙事。

- 事件：成功的玩家放置 `BLOCK_PLACED`；主手右键锚点 `USE_BLOCK`。
- 动作：`set_block`、`spawn_creature`、`give_item`。
- 所有规则都声明非空气 `(0,0,0)` 锚点；最后放置的可以是任一构件，不限顶块。
- 右键有 `heldItem` 时消耗匹配堆叠；未声明时要求空主手。蹲下保留普通放置/使用。
- 四向旋转包含坐标及原版方块方向状态；只读取已加载区域，没有周期性全世界扫描。
- 状态按包、维度、位置和 mechanic ID 保存。支出、动作与状态一起提交，失败回滚；创造模式也消费 heldItem。
- 原生准备限制每触发方块索引 512 候选／8192 最坏单元检查；超限明确报错，可减少重叠或旋转。
- 每维度最多 16384 锚点实例，每 tick 每玩家 16／每维度 128 次触发。损坏账本保留原文件并阻止绑定，不清空已使用装置。
- 失败时逐项尝试补偿；若原生／第三方钩子令补偿也失败，持久隔离账本并停止后续交互，再载入时阻止绑定以便检查。
- 不宣称所有第三方钩子均可逆，也不宣称世界文件与玩家文件之间的断电原子保存。

**没有扔物检测、tick 脚本、命令脚本、背包扫描或任意事件解释器。** 需要材料祭献时，
规则和玩家提示应明确采用“主手持材料、右键锚点”；未安装的动作仍是显式待定设计。

完整字段及预算由 [`mechanics` 契约](../core/src/main/resources/prompts/contract/mechanics.system.md)
提供，MCP 入口为 `worldsmith_get_content_contract(module="mechanics")`，通过
`worldsmith_put_content_modules` 原子提交，也支持 `write_pack` 的 inline `mechanics`。
发布验证引用、模式与循环边界；成功保存不等于已运行游戏或完成实玩。

完整世界从 WorldBible 的 RULE 节点出发，将 `{kind:"mechanic",id:"..."}` 分配给任务书。
审核证据指向真实 `pattern`、`heldItem`、`actions` 与状态转换；字段修改会令原审核过期。
计划关系可使用 `uses_block`、`consumes_item`、`grants_item`、`spawns_creature`。
这些链接是实际字段的覆盖检查，不能代替材料来源与循环经济设计。没有机制承诺时可提交
空库；命名承诺过的装置必须真实落地。

参见[三种可组合示例与验证步骤](examples/mechanics/README.md)。旧格式 1–6 被显式拒绝；
本次格式变更不遍历、迁移或修改本地旧包与存档。

## 玩家如何读懂机关

旅程日志的 `activate_mechanic` 目标使用稳定的 mechanic ID 打开说明，不靠目标显示名反查。
已解锁／可领奖／已领取任务都保留说明入口；锁定任务没有深链入口。入口不依赖已摆好的构型。

说明直接投影不可变规则，显示触发方式、主手成本、方块材料与消耗数量、按 Y 从下到上的构型层、
相对锚点的 X/Z 方位、旋转条件、状态／冷却和动作效果。**明确空气格不同于未声明格**；
放置用的建材与右键消耗的主手物品分开列出。改了规则就改变说明，不再手抄一份攻略 JSON。

图纸离开现场也能阅读。现场诊断是玩家手动点击的只读操作：检查准星指向的锚点，
服务器核对同世界、任务可读性、玩家状态、距离与区块加载状态，再报告构型／材料／冷却等原因。
它不触发机关，不补方块、不扣材料、不创建实例账本，也不做每 tick 区块扫描。
世界切换和过期查询回复不会被当作当前装置的结果。

作者仍要提供**现场线索与可到达的材料来源**：在实际结构上添加短刻文，用任务描述指出地点，
在物品说明中写明主手和使用对象。图纸解决“怎么摆”，不会替作者生成建筑、箱子、掉落或钥匙。
可复现的小流程见[灯火旧庭探索包](examples/mechanic-discovery/README.md)。
